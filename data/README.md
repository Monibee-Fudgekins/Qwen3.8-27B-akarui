# Data

This directory holds the versioned training corpus for Qwen3.8-27B-akarui.
Raw competition data is **not** committed to the repository; only
manifests, schemas, and small derived artifacts live here.

## Layout

```
data/
├── README.md            # this file
├── manifests/           # one manifest JSON per dataset version (see schemas/)
└── schemas/
    ├── trajectory.schema.json   # JSON Schema for one trajectory record
    └── manifest.schema.json     # JSON Schema for a dataset manifest
```

Dataset files themselves (JSONL trajectories) are built by
`src/data/dataset_builder.py` and stored outside the repository or
as a versioned release artifact. A manifest in `data/manifests/`
records the SHA-256 of the assembled dataset file, so any training
run can be reproduced from the manifest alone.

## Trajectory records

Each trajectory is one JSON object per line (JSONL) conforming to
`data/schemas/trajectory.schema.json`. Required fields:

- `competition_id`, `source_url`, `dataset_provenance`, `license`
- `task_description`, `input_schema`, `target_definition`,
  `evaluation_metric`, `training_validation_strategy`
- `reasoning_summary`, `generated_code`, `execution_environment`,
  `execution_output`, `errors_and_debugging` (list)
- `validation_score` (number, or `null` when no score was measured)
- `final_outcome`, `dataset_version`, `collected_at`
- `category` — one of:
  `competition_analysis`, `programming_debugging`,
  `feature_engineering_modeling`, `validation_statistics`,
  `experiment_optimization`, `ensembling_postprocessing`,
  `submission_workflows`

Target category proportions (initial sampling targets, not hard
quotas): competition analysis 20%, programming/debugging 20%,
feature engineering/modeling 20%, validation/statistics 15%,
experiment optimization 10%, ensembling/post-processing 10%,
submission workflows 5%.

## Manifest rules

Every dataset version ships a manifest (`data/manifests/<version>.json`)
conforming to `data/schemas/manifest.schema.json`, containing:

- the dataset version and creation timestamp,
- every source's URL, license, SHA-256, collection date, and
  filtering decisions,
- record counts per category and in total,
- the SHA-256 of the assembled dataset file,
- the list of excluded competitions (the held-out benchmark
  competitions in `evaluation/benchmark_manifest.json` must always
  be excluded from training data).

A manifest with a missing or empty required field is invalid.
Dataset hashes are computed with
`src/publishing/provenance.compute_file_hash`.

## Licensing rules

- Only material whose license permits redistribution and training
  use may enter the corpus. Record the exact license per source in
  the manifest.
- **Never include:** private competition data, hidden test labels,
  private notebooks, leaked solutions, restricted datasets, or
  future leaderboard information.
- When a source's license is unclear, exclude it and record the
  decision in the manifest's filtering notes.
- Synthetic tasks and trajectories generated by Akarui itself are
  recorded with `dataset_provenance` stating that they are
  internally generated.

## Adding data

1. Collect from a permitted source (Kaggle public competitions,
   public datasets, public GitHub repositories with compatible
   licenses, Hugging Face datasets with compatible terms, or
   internally generated tasks).
2. Build trajectories with `src/data/dataset_builder.py` and
   validate them against `data/schemas/trajectory.schema.json`.
3. Deduplicate against previous versions
   (`src/data/deduplication.py`).
4. Write the dataset file, compute its SHA-256, and add a manifest
   under `data/manifests/`.
5. Verify the held-out benchmark competitions are absent from the
   new version before any training run uses it.
